# 06 · 呈现适配（按你的能力出画面）

> 什么时候读：第 0 步判断走哪条路线；第 6 步出画面。
> 不管走哪条路线，**先写同一份 `book.json`**，再按能力出画面。同一个问题在不同 agent 上跑，内容结构一样，画面各不相同。这正是它是一个工作流、不是一个产品的地方。

## 先判断你能做什么

| 你的能力 | 路线 | `render.route` | 画风建议 |
|---|---|---|---|
| 能直接生成图片（例如 Codex 内置的 `image_gen`、Gemini） | 生图路线 | `image` | 水彩绘本、彩铅、剪纸，家长选 |
| 只能写代码（例如 Claude Code、ZCode） | 代码画图路线 | `code` | **积木画风**：几何形、平涂色块、干净的线 |
| 能做视频或动画 | 视频路线 | `video` | 先按上面任一路线出静态页，再做成动画 |

告诉家长你能做哪几种，让他选（问卷第 7 题）。**代码画图不是缺陷**：几何、简洁的「积木画风」正好贴合建筑师拆解法：剖面、构件、结构一目了然。

## 生图路线（`image`）

1. **先出角色参考图**：用 `guide.image_anchor` 写一张「正面全身、背景干净」的角色图，存成 `images/guide_ref.png`，路径写回 `guide.reference_image`。给孩子看过、孩子说像了再往下
2. **逐页出图，每页都带参考图**：提示词用这页的 `visual.image_prompt`（里面已经有 `image_anchor`），再补一句「参考图只用于角色身份，保持外形、颜色、比例；横向 3:2」
3. 按页序存成 `images/p01.png`、`images/p02.png`……，路径写回各页 `visual.image`
4. **并排检查**：全部出完后把参考图和各页放在一起看，颜色、比例、特征跑掉的那页重出
5. 跑 `validate_book.py`，再跑 `render_book.py`

**时间**（2026-10-10 在 Codex 命令行实测，gpt-6.1-sol）：第一张约 67 秒；带参考图换场景约 99 秒一张，出图 1536×1024。一本 6–8 页串行出图约 10–15 分钟。省时间的办法：先不出图，渲染一版无图的 HTML 给家长看旁白和家长卡，**家长认可了内容再出图**。

Codex 的具体调用方法见 `assets/imagegen_notes.md`。

## 代码画图路线（`code`）

1. **先画角色**：`images/guide.svg`，固定颜色、比例、部件，路径写进 `guide.reference_image`。给孩子看过再往下（档案里已有角色卡的，见 03 的说明，不用等）
2. **每页一个 SVG**：`images/p01.svg`、`images/p02.svg`……
   - 画布 `viewBox="0 0 1536 1024"`（3:2），和生图路线的比例一样
   - 角色用同一段代码（同一个 `<g>` 或 `<symbol>`），只改位置、大小、朝向
   - 按 `visual.description` 画：这页的**主体**要大、要清楚，角色在旁边带路
   - 积木画风：几何形、平涂色块、圆角，暖色浅底；每页主色不超过 5 种（不算角色本身的颜色）
   - 画面里可以有少量标注字（如「果皮外墙」），字号要大，不超过 3 处
   - 只用内联的形状和渐变，不引用外部图片、字体或网址
3. 路径写回各页 `visual.image`
4. **检查画面**：按原尺寸渲染成 PNG 再看，例如 `rsvg-convert -w 1536 -h 1024 p01.svg -o p01.png`。⚠️ 不要用 macOS 的 `qlmanage` 生成缩略图来检查：它出正方形缩略图，会裁掉或压扁画面，导致误判「缺东西」
5. 跑 `validate_book.py`，再跑 `render_book.py`

## 视频路线（`video`）

先按上面任一路线把静态页做完、家长放行，再做动画：每页一个镜头，镜头里角色的动作就是 `visual.description` 写的动作，旁白用 `narration` 配音。视频文件放 `video/`，`book.html` 仍然要有（家长卡和最后一页在里面）。

## 隐私：画面交给谁

- 生图路线：提示词和参考图会发到生图服务商（例如 Codex 发给 OpenAI）；有的生图工具还会在它自己的缓存目录里另存一份原图（2026-10-11 实测：Codex 存在 `~/.codex/generated_images/`），不受你指定的输出文件夹控制
- 有些 agent 在「看」图片检查画面时，会把图片上传到它的服务器（2026-10-10 实测：ZCode 检查画面时上传到了智谱的服务器）
- 所以：**孩子的真实照片、录音不要当参考图，也不要交给会上传图片的工具去看**。角色参考图只用你生成的图
- 详见 README「数据与隐私」

## 渲染出来的 `book.html` 有什么

`render_book.py` 把 `book.json` 和图片打包成一个单文件 HTML，断网能打开：一屏一页、能左右翻、每页有「读给我听」（浏览器自带朗读）、每章后有追问口、最后一页留给孩子并能导出 `feedback.json`、家长卡折叠在最后；没放行时顶部有「家长预览版」横幅。

不想要 HTML 的平台（比如只能输出文字的聊天机器人）：把 `book.json` 的内容按页输出成文字也可以，但家长卡、追问口、最后一页一样都不能少。
