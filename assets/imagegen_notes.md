# 内置生图操作说明（Codex）

- 使用 Codex 内置工具 `image_gen.imagegen`；提示词和参考图交给 OpenAI 图像生成服务。
- 不需要自己配置 API key；不要把孩子的真实照片、姓名、住址、学校等隐私交给生图服务。
- 本说明依据当前可用工具接口；本任务没有实际调用生图，以下时间是预算，不是实测。

## 先定向导
1. 用 `guide.image_anchor` 原文构成角色参考图提示词，同时写上角色色彩、画风、正面全身及清楚的外形。
2. 调用 `image_gen.imagegen`，参数 `prompt` 为上述文字，`transparent_background=false`。
3. 全新生成时不传 `referenced_image_paths` 或 `num_last_images_to_include`。
4. 工具完成后检查图片，再把返回的本地图片复制到书目录的 `images/guide_ref.png`。
5. 工具默认保存位置在 Codex 的生成图片目录；不要猜文件名，以实际工具结果为准。
6. 把相对路径 `images/guide_ref.png` 写回 `guide.reference_image`。

## 逐页生成
1. 先用 `view_image` 查看本地参考图；之后每次调用都传
   `referenced_image_paths=["角色参考图的绝对路径"]`，`transparent_background=false`。
2. `prompt` 使用该页 `visual.image_prompt`，保留 `guide.image_anchor` 原文。
3. 补充「参考图只用于向导身份；保持外形、颜色、比例和画风；本页场景按提示词；横向 3:2」。
4. 不同时传 `num_last_images_to_include`；只有参考图没有本地路径时才使用这个参数。
5. 每页单独调用一次；检查角色是否一致、动作与原理是否正确，必要时做针对性修改。
6. 按全书正文顺序存成 `images/p01.png`、`images/p02.png`……，写回各页 `visual.image`。
7. 用实际返回图片确认文件格式与尺寸；需要 PNG 时确认返回格式，不要仅改扩展名。
8. 写回后运行校验与渲染脚本；生成工具返回的图片需要复制进书目录才能随书搬迁。

## 尺寸、时间与省时
- 当前工具没有独立的 `size`、`quality` 或输出路径参数；可以在提示词请求横向 3:2。
- 不能保证工具的具体像素尺寸或耗时，以返回文件为准；HTML 会完整显示，不裁切。
- 工具说明提示每次约需几分钟；这是操作预算，实际可能超出，没有实测耗时。
- 6–8 页加一张角色参考图，串行约 7–9 次调用，应预留数十分钟，重试另算。
- 先一次性准备全部页的提示词，先校验 JSON；确认参考图后再逐页出图，减少返工。
- 草稿阶段先用无图片 HTML 确认旁白与家长卡；只为确定保留的页生图。
- 参考图能帮助跨页一致，但不保证完全一致，必须逐页检查；不要引用现成 IP 角色。
- 保存原文件，修改图另存版本；不要覆盖未经授权的既有图片。
